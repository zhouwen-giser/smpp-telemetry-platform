# Known limitations

1. The real Prometheus plane is qualified, but no real ProviderOps OTLP record from the external SMPP Runtime reached this isolated qualification Collector. The final Runtime snapshot reported 24,689 audit export failures, and the qualification deliberately did not mutate external Runtime configuration. A source-derived envelope generated by current SMPP code passed the complete Collector → Processor → WAL → ClickHouse → Query path, but it is not presented as a live Runtime emission.
2. `pnpm typecheck` still fails on broad baseline TypeScript debt: existing JavaScript-style `.ts` files omit class property declarations and parameter types. Strict compiler settings were preserved. Build, `pnpm test` (28/28), and deployment qualification pass.
3. No real SDAR-origin task correlation record was available from the Runtime. Explicit N:N relation projection is covered by a 2×2 test, and the source-derived record proves trace/span and source lineage preservation, but no synthetic relation is claimed as live evidence.
4. Qualification certificates and secrets are operator-supplied and were generated only in a disposable `/tmp` directory. They are not part of the delivery bundle. Production must issue certificates from its approved PKI and bind OTLP only to the required private interface.
5. The user-directed branch policy overrides the work package's isolated-branch instruction: work was committed directly to local `main`. No remote push, PR, tag, merge, release, or SMPP mutation was performed.
